## 2.5 ⭐ 根因已确认并已修复：门在「被权重自己抽稀过」的帧集上测量（循环论证）

离线实测（`tools/diagnostics/diagnose_window0_offline_reweight.py`，零 GPU，
`4W53/output_v3_seed20260908/solvent_leg/vanishing`，window 0，K=5 态 × N=500 帧）。

生产的采样分布是 `p(x) ∝ exp(-β(base + bias))`，目标态 k 是
`∝ exp(-β(base + energies[k]))` ⟹ raw 重要性权重
`w_n ∝ exp(-β(energies[k,n] - bias[n]))`。逐目标态算 `ESS = 1/Σw²`：

| 目标态 k | ESS | ESS/N | top-1% 权重 |
|---|---|---|---|
| 0 | 241.93 | 0.484 | 0.084 |
| 1 | 138.84 | 0.278 | 0.142 |
| 2 | 31.52 | 0.063 | 0.266 |
| 3 | 8.00 | 0.016 | 0.441 |
| **4** | **3.58** | **0.007** | **0.601** |

**最差目标态的 raw ESS = 3.58，门槛是 20 ⟹ 窗口 0 本该被拦下。**

而落盘的 `window_overlap_diagnostics[win 0]` 写的是：
```
raw_min_absolute_ess = 47.95        top1pct_raw_weight = 0.168
```
**差 13 倍，而且方向是把"该拦"报成"健康通过"。**

这比第 3 节的壳假设更直接地解释了第 2 节那个反常组合（ΔG 错 +20.79、门却全绿）：
**门不是对这个失效模式"失明"，门是算错了数。**

### 根因（已定位、已数值证明）

**不是**口径不匹配，也**不是** min 取错组 —— 这两条我都排除了：pymbar 的
`compute_effective_sample_number()` 在这批数据上与 raw 单参考 ESS **逐位相同**
（都是 `[241.93, 138.84, 31.52, 8.00, 3.58]`）。

真因在**喂进去的帧集**。`ibs_engine.py:~17944` 处，算门之前先做了去相关子采样：

```python
sub_idx, g_val, g_worst = _decorrelate_by_worst_target_state(u_kj_raw, bias_kj, ...)
```

而 `_decorrelate_by_worst_target_state`（`:17518`）用的序列是

```python
series = (u_kj_raw[k] - bias_kj) / kt      # ← 它的指数**就是**重要性权重
idx_k, g_k = subsample_series_by_autocorrelation(series)
```

**拿权重挑样本，再用挑出来的样本量同一批权重的退化程度 —— 循环论证。**
抽稀恰好削掉权重的自相关暴涨段，剩下的权重自然看起来均匀。

数值证明（window 0，500 帧，实测 g=2.13 → 保留 235 帧）：

| | 帧数 | 逐态 raw ESS | min | ESS/N | max top1% | 门 |
|---|---|---|---|---|---|---|
| 去相关**前** | 500 | 241.93 → **3.58** | 3.58 | 0.0072 | **0.601** | ❌ 两项都挂 |
| 去相关**后** | 235 | 116.69 → **47.01** | 47.01 | **0.2000** | 0.170 | ✅ 放行 |

复现值 47.01 对上落盘的 47.95（残差来自 `valid_mask` 与分段去相关）；
落盘 top1% 0.168 对上复现的 0.170 ⟹ **两个受门量都受同一个循环论证影响。**

扔掉 53% 的帧让 ESS/N 涨 **28 倍** —— 对合法 ESS 估计数学上不可能，只可能来自
"剔除与权重相关"。更糟的是形状：逐态单调崩塌从 **68 倍**（241.93→3.58）被抹平到
**2.5 倍**（116.69→47.01），**门要探测的信号本身被消掉了。**

### 修复（2026-09-01 已落地）

`ESS_GATE_PROTOCOL_VERSION 4 → 5`。去相关**保留**（MBAR 的 `n_k` 需要它，
而且该函数换用权重序列本身是有充分理由的，见其 docstring），只是**不再用来算这道门**：

- 受门的 `raw_min_absolute_ess` / `raw_min_ess_ratio` / `raw_ess_ratio_per_lambda` /
  `top1pct_raw_weight` 改在**去相关之前**的帧集上算（复用同一个
  `_ibs_reweighting_quality_diagnostics`，不新写数学）；
- 新增 `raw_gate_n_frames_pre_decorrelation` 记录门实际用了多少帧；
- 旧口径全部保留为 `raw_*_post_decorrelation`，**历史产物对账靠它**
  （v4 及更早落盘里的 `raw_min_absolute_ess` 就是这个值）。

⚠️ `ESS_GATE_PROTOCOL_VERSION` 已核实**不进任何缓存/协议指纹**
（`abfe_pipeline.py` / `runabfe.py` 里完全没有它，只出现在诊断输出 dict），
所以这次升版**不会让任何已完成的 GPU 结果失效、不逼重跑**。

**那次拒绝留下的盲区就是这里**：|ΔF| 不能做**布点**坐标，但它就是**窗口分组**

## 3.（已作废，见 §2.7）为什么门看不见它 —— 壳机制候选，**已被证伪**

窗口 0 覆盖 λ_vdw = `[1.0, 0.9209, 0.8486, 0.7827, 0.7236]`，均值 **0.855**。

- WCA 防护壳（Group 4）强度 = `ibs_engine.py:4915`
  `4.0*lambda_shield*(1.0-lambda_shield)*step(rc-r)*eps_wca*…`
- `lambda_shield` 每窗口设为**本窗口 λ_vdw 均值**（`ibs_engine.py:7620-7621`，
  实际 `setParameter` 在 `run_all_windows` 里）
- ⟹ 窗口 0 的壳强度 = `4 × 0.855 × 0.145` ≈ **0.50**，**半强度开着**
  （别按"λ_shield 接近 1 ⟹ 壳接近 0"直觉判断：强度是抛物线，不是 λ_shield 本身。
  这条已在记忆里栽过一次。）

而 `ibs_engine.py:4676-4687` 自己写明了关键性质：

> the WCA shield **only cancels out of same-frame, same-window energy
> differences between states** (it has the same lambda_shield for every k in a
> window), **it does not disappear from the sampled trajectory**.

把这句和第 2 节合起来就是失明的机制：

> 壳对窗口内每个 k 都相同 ⟹ 它从**所有窗口内**的重加权诊断里精确抵消
> （raw ESS、top-1% 权重、min overlap 都是在窗口内算的，见 `ibs_engine.py`
> 约 18150–18200 的 `_overlap_record`，全部在 `for w_idx` 循环体内）；
> 但它**不**从被采样的构型系综里抵消。
>
> 于是：窗口 0 的系综是在半强度壳下采的（壳把水挡在配体该占的区域外），
> 目标态 λ_vdw=1.0 无壳；重加权拿不回无壳构型，**而所有门都算不出这件事**，
> 因为门度量的是"已采到的构型之间的散布"，壳在其中是共模项。

⚠️ **§2.5 修完之后，这一节的解释力已经缩小 —— 别再拿它当主线。**
"窗口 0 的门为什么没拦住"已经有了答案（门算在被权重抽稀过的帧集上，v5 已修；
修好后窗口 0 两项判据都挂）。所以**不再需要**"门对共模项结构性失明"来解释门失效。

本节剩下的作用只是一个**候选机制**，回答另一个仍然开放的问题：
**为什么被采的系综本身是错的**（+38.59 而真值 −3.544）。壳把水挡在配体该占的
区域外、而目标态 λ_vdw=1.0 无壳，这与"误差集中在完全耦合端"相容。

但它**未被证明**，而且注意 §4-A 已证：壳的效应完全不在权重里，所以它
**无法离线判定，只能靠重采样**。顺序上排在 §7 第 2 步之后。

## 4. 两条判定性验证（都不需要新物理，二选一）
