## 2. 为什么训练帧是 `pre_equilibration.dcd`

`X_k(x) = U^sc_k(x) + A_k·[B_φ(x) − B_0] − f_k`。`B_φ` **只进 sampling score，
physical target 永远不含它**，对任意**冻结**的偏置 MBAR 都无偏。

⟹ **训练帧源不是正确性问题，只是「这个采样增强项好不好用」的问题。**

由此塌掉的三条顾虑（它们只在**做 A/B 时**成立，普通生产跑只有一条臂）：

| 顾虑 | 为什么在单臂生产跑上不成立 |
|---|---|
| `sampling_score_sha256` 变 run-dependent、两臂不共用同一把尺子 | 只有两臂时才叫问题 |
| 拿缺构型的帧拟合会把缺掉的态焊进模型 | 那是 stage2 单系综自己的老问题（门对慢模态失明），不是重训创造出来的 |
| 违反预注册 | 预注册约束的是 A/B 的可比性 |

于是选最便宜、最一定存在的那条轨迹：名字固定、每个 run 都有、零额外 GPU，而且在
stage 2 **之前**就产出 —— 新配体跑 stage 2 之前根本没有 `energies.npy` /
`sampling_states.npy` / `residual_basis.npy`，鸡生蛋。**有多少帧用多少**，不抽稀、
不设帧数下限。

EXP-033 §5 P1 原文写「用那次 run 自己的每窗口产物」，**不是物理要求** —— 是因为当时有
rerun1/2/3 三条平行实验、LORO 可以按**独立 run** 分折。而 LORO held-out 本来就不是
验收判据（§4），单条轨迹按时间切三段只为内层 CV 选 λ 服务。

**已知代价**：预平衡是 λ=1 全耦合单系综，`B_φ` 往解耦端是外推。那是**好不好用**的
问题，交给 EXP-027 U3 口径上机判。

### 3.1 `_stage_protocol_key` 收窄（独立的一条真 bug）

`residual_sampling` 原来**无条件**进每个 stage 的缓存身份，但运行期真正用它的只有
vanishing。⟹ 打开开关会让 **decharging(Stage 1)** 的 stage 缓存无谓失配、整段约 28
分钟白重跑。

它有**两条**进指纹的路径，两条都得收窄：

1. 显式插入的 `payload["residual_sampling"]`
2. `run_config` 里那份（`run_full_pipeline` 会往 `_last_run_config` 塞）

现在运行期判据与缓存身份判据读**同一个** `RESIDUAL_SAMPLING_STAGES =
frozenset({"vanishing", "vanishing_rescue"})`，不会再漂开。关着的时候两条都是 no-op
⟹ 既有指纹逐位不变。

> 交接文档 §4 第 1 条说「预平衡 / attachment / decharging 的缓存全部失配」是**高估了**：
> `pre_equilibration_identity_fingerprint` / `_rebalance_fingerprint` / `_preopt_protocol_key`
> 三份都不带 `run_config`，不受影响；`_stage_protocol_key` 也只被 `"decharging"` /
> `"vanishing"` 两个 stage 调。实际只有 Stage 1 那一处。

### 3.2 延迟绑定共用同一段 fail-closed

`attach_residual_sampling_runtime()` 是**唯一实现**，构造期与延迟绑定都走它。别在
`runabfe` 里重抄赋值 —— 重抄就会绕过 `no_residual_twin` 与 plugin identity 两道门。

绑定时机安全，是因为残差只进 vanishing 的缓存身份，而那份指纹在 `run_full_pipeline`
内部、即绑定之后才构造。

### 3.3 两段 vdW 共用一份权重

权重**绑配体不绑体系**（`RETRAIN_LOCAL_RESIDUAL.md` 的表：复合物腿↔溶剂腿不用重训），
所以一次重训两条腿共用。溶剂腿原来读的是 `config.outer_lambda_resource_manifest`
（**冻结**那份），重训产出到不了它 ⟹ 新配体会在溶剂腿撞身份闸门，而且是在复合物腿
整段跑完之后才炸。现在三个调用点统一读 `_residual_resource_manifest`。

## 5. 门是怎么定的（这一节最容易被改坏）

`B_φ` 的职责是**让配体解耦时整体别散架**（提高窗口内 λ 态之间、以及相邻窗口共享态
那条缝上的混合），不是一个要逐点复现的物理模型。按精度标准硬拦会拦掉本来能跑的 run。

| 情况 | 处置 |
|---|---|
| tanh 改形 >10% | **记录 + 警告，不拦**。§2.3B 实测线性量程 ±28~40 kT 而 `b_max=10`，改形是**预期**会发生的；饱和段仍是朝正确方向的推力 |
| B 本来就小（信号弱） | **警告，不拦**。这是个结果，交给 U3 上机判 |
| tanh 把离散度压塌（帧全压到同一侧） | **fail-closed**。B 退化成常数 → 被 f_k 整个吸收 → 开了等于没开，跑完一整轮 GPU 才发现 |

判别量是 `std(deployed)/std(linear)` 的**塌缩比**，不是绝对离散度 ——「B 本来就小」和
「tanh 把它压平了」是两回事，混成一条会误杀小而健康的 B。

## 6. 仿射 ρ（payload 层面唯一的技巧）

payload 的 ρ 形状是硬写的 `Linear(1,16) → SiLU → Linear(16,16) → SiLU → Linear(16,1)`
（`openmm_plugin.load_r1_payload` 逐字段读），而闭式解只解得出 `pair_weight`。

做法：`SiLU(z) = z·sigmoid(z)` 在 `sigmoid(z)` 舍入到 `1.0` 时**精确**退化成恒等
（float64 要 `e^(−z) < eps/2`，即 `z > 36.7`），于是用大偏置 `L = 60` 把 ρ 构造成仿射，
斜率折进 `pair_weight`：

```
h0 = [s·q + L, L, …, L]      (w0 = s·e₀, b0 = L)
z2 = [s·q + L, 0, …, 0]      (w2 行0 = e₀ᵀ, 其余 0, b2 = 0)
rho(q) = g·(s·q + L),  g·s = 1
rho(q) − rho(0) = q
```

三条别改坏的：

- **`b2` 取 0，不是再叠一个 `L`**：次层预激活 `s·q + L ≥ 45` 本来就够大，叠第二个
  偏置只会白丢一半精度。
- **不是逐比特恒等**。SiLU 那一步是精确的（有单独测试钉住），但 `(s·q + L) − L` 会吃
  低位，绝对误差 `eps(L)/s`，由 `affine_rho_absolute_error_floor()` 报出来并写进 payload。
- **斜率缩放要留余量**。直接取 `MAX_Q / q_bound` 会让 `s·q_bound` 落在
  `15.000000000000002`，`>= 45` 那道判据会因为一个 ULP 判否。现在缩到 0.99。

## 9. P3（通用权重）已划掉（用户 2026-09-12 拍板）

**不做。** 理由不是"暂时没空"，是**前提没了**：P3 存在的唯一目的是让一份权重服务
整个配体系列，而它值得做的前提是"逐配体重训很贵"。P1 落地之后重训是一次闭式求解，
这个前提不成立了。EXP-033 §0 本来就写着「拟一份跨配体通用权重」🔴 不推荐
（§2.3C 第 3 条：同一配体、同一条 λ 梯、三条独立轨迹都还没把系数钉住）。

**划掉它在技术上也是自洽的，不只是省事。** §1 第 3 条那个「非外延的输出头」
（全局 tanh 套在对原子求和之外 ⟹ B 不是外延量，换配体尺寸就换工作点；§2.3B 实测
41 原子 `dB/dS` 中位 0.88 不饱和，~80 原子进死区）**只有在跨尺寸迁移权重时才咬人**。
逐配体重训的话 `softlift.derived_r1_config()` 已经按配体原子数缩 `b_max_reduced`，
工作点自己跟着走。

⟹ 于是也**不需要改 CUDA kernel**（P3 的「逐原子有界」要替掉全局 tanh），
就不用拖 `KNOWN_PLUGIN_SOURCE_SHA256` 两处同步 + G0–G4 重验 + 成本门重跑。

**用词澄清**：这条链上**没有 teacher**（§2.1：出厂 R1 是 `direct_gap`，信号纯 MM，
`bidirectional_gap_variance_loss` 只吃 MM ledger 的 `adjacent_gap_reduced`）。
所谓"蒸馏"蒸的是 **MM 哈密顿量自己的相邻 gap 结构** → 一个便宜的局部函数。
**不是**拿 MACE 当教师 —— 那条是 §6「明确不做」的第二行，会把 per-system MACE 标注
重新引回来。

⟹ **剩下唯一开着的是 P2**：ridge 臂 vs 出厂非线性臂，U3 口径上机（window-0 utility +
ΔG 一致性，两臂各自标定并冻结自己的 f_k）。它决定的不是"要不要通用"，而是
"这个闭式臂到底值不值得留"。

## 10. A/B 怎么走（别踩）
