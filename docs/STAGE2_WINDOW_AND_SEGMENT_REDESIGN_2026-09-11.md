## 1. 预热早退：占据判据事实上成了唯一放行门

**症状**：4/4 跑到 stage2 vanishing 的 run 全部 `IBSWarmupConvergenceError`，
`validation_attempts ≈ 0` —— local-MBAR loose gate（**唯一**的生产入口判据）一次都没
评到。

**根因**：`ibs_engine.py` 的 VALIDATE 早退在完整 gate 求解**之前** `continue` 回
learning。只要它每个 freeze cycle 都命中，本窗口就一次判据都评不到，占据就事实上变成
了唯一放行门——正是 v29 注释里"否则会把这个宽松 10 kJ/mol 门偷偷变成严格收敛门"要
禁止的。失败后本该接手的 3-way router / damped 直接重验分支从未执行过。

**为什么早退会一直命中**：`IBS_WARMUP_FRAME_STRIDE_STEPS = 250`，而失败窗口实测
`g = 36.69` 帧 ⟹ 关联时间 τ = 9172 步。预热里每个常数都只有 1–5 τ：

| 量 | 帧/步 | 折合 τ |
|---|---|---|
| 学习更新 minibatch | 40 帧 = 10,000 步 | **1.09** |
| 早退探针 | 40 帧 = 10,000 步 | **1.09** |
| loose gate 预算 | 200 帧 = 50,000 步 | 5.45（需要 10） |
| 整窗预算 | 555,000 步 | 60.5 |

**控制器每次更新只有一个独立样本**——这才是限幅振荡（实测 82–92% 的更新贴在
4 kT = 9.98 kJ/mol 上限）的成因，不是增益太大。

**改动**：早退加 `ever_completed_a_validate_attempt` 守卫，本窗口拿到至少一次完整 gate
评估之前不允许早退。协议版本保持 33、缓存兼容。

⚠️ **不要删掉早退探针**。删了每个 freeze cycle 从 1 批变 5 批（+40,000 步/周期），
而门本来就哑——那是把"便宜的错判"换成"昂贵的没判"。

## 2. 规范陷阱：`energies.npy` vs `sampling_states.npy`

`energies.npy` 比 `sampling_states.npy` 多一个**逐 λ 态的常数** = LJ 长程尾项（在分析
侧的目标能量里，**不在采样哈密顿量里**）。逐态常数**不是共模**，不会在 logsumexp 里
抵消，会改变形状。

恒等式 `bias == -kT·logsumexp_k(-(u_k - f_k)/kT)` 在真实产物上的对账：

| | w0 | w1 | w2 | w3 |
|---|---|---|---|---|
| `energies − sampling_states` 逐态 sd | 5.8e-14 | 2.8e-14 | 2.2e-14 | 1.9e-14 |
| 用 `energies` 对账 | 0.7351 | 0.3734 | 0.1816 | 0.0941 |
| 用 `sampling_states` 对账 | **0.0000** | 0.0000 | 0.0000 | 0.0000 |

那个"随窗口单调下降"的形状就是**尾项随配体解耦而缩小**，不是 f_k 过期。
（f_k 也不可能过期：loader 拿 `production_entry_f_k` 逐位校验，不符直接 raise。）

**根因**：`_load_ibs_window_outputs_from_dir` **只在 residual 臂**返回
`sampling_state_energies`；baseline 臂拿不到，生产侧的 local MBAR 就会在含尾项的
`energies` 上求解。已修：显式从盘上取，并加 1e-3 的自洽门（对不上跳过该窗口，
**不中止 stage**）。真实数据上对账 1.7e-5（非零只因 float32 落盘）。

## 3. 加帧之前必须重标定 f_k

**观察**（cyclod rep1，两轮 rescue 500k→1M）：

| | window_2 | window_3 |
|---|---|---|
| ESS_ratio | 0.391 → **0.211** ↓ | 0.0415 → 0.0495（几乎不动）|
| absolute_ESS | 6.26 → **2.53** ↓ | 1.62 → 3.91 ↑ |
| N_decorrelated | 16 → **12** ↓ | 39 → 79（正好翻倍）|
| top1%_raw_weight | 0.048 → **0.074** ↓ | 0.487 → 0.380 ↑ |

样本翻倍后 window_2 六项里五项**变差**。绝对量老实跟着帧数走，**比值纹丝不动**。

**这同时推翻了一条被反复引用的结论**：`STAGE2_ROOT_CAUSE_2026-08-28.md §3.2` 的
"瓶颈是 span 不是帧数"，是在**冻结的、可能本来就错的 f_k** 下测的——它没把 span 和
f_k 分开。f_k 偏了 ⟹ 混合分布本来就集中 ⟹ 加帧只是往同一个偏斜分布里加更多帧。

**f_k 确实偏了**（真实产物离线重解，零 GPU）：

| 窗口 | 帧数 | 相邻位移 | 最大绝对位移 | g |
|---|---|---|---|---|
| w0 | 500 | 1.915 | 3.201 | 2.5 |
| w1 | 1000 | 2.399 | 3.555 | 24.2 |
| w2 | 2000 | 1.398 | 2.416 | **78.2** |
| w3 | 2000 | 2.297 | 3.743 | 17.8 |

1.4–2.4 kJ/mol 的相邻差误差 = 0.56–0.96 kT，四个窗口**全部**超过 0.5 阈值。对应的
warmup loose gate 余量是 7.211 / 3.675 / 4.548 kJ/mol——**都合法，都 < 10**。
（gate 只用 200 帧判、只要求 < 10 kJ/mol ≈ 4 kT。）

**合成对照（12 seed，真值 14.0）**：

| 方案 | 偏差 | 实际 RMSE | 报告 σ |
|---|---|---|---|
| 天真拼接（两段 bias 摞成一个采样态）| +0.121 | 0.250 | 0.342 |
| 只用段2 | −0.014 | 0.114 | 0.060 ⚠️ 低估 2 倍 |
| 两段合并（补齐交叉能量）| −0.004 | 0.097 | 0.085 |
| **同预算全花在新 f_k** | +0.008 | **0.060** | 0.042 |

⟹ **主项是"f_k 换对"，合并只是捡回沉没成本（~15%）。**

## 4. 段2 被采纳而不是合并，随后又被丢掉

**三个串连的 bug**：

1. **采纳而非合并**。段2 一采纳就扔掉段1 的帧（w1/w2/w3 里 2/3 到 4/5 的 ESS）。
2. **随后被 bridge rescue 丢掉**。它从写死的 `output_dir/vanishing` 重新加载，最终
   报的数**一帧段2 都没有**，`stage2["f_k_recalibration"]` 也被那次重赋值冲掉——
   这就是"指标一个 JSON 都没落盘"的同一个根因。
3. **段2 从基础预算重开**（500/500/500/500 vs 段1 的 500/2000/2000/1000）。除了扔掉
   采样，还有个隐蔽后果：**更短的序列让新段在所有 g/ESS 诊断上系统性显得更好**。

   实测：段1 的 w3 全长 1000 帧 g = 202.9；把它自己截到 500 帧变成 13.9 / 31.0，
   跟段2 的 27.8 同一档。**段2 的"7 倍改善"是序列长度假象。**

**还有一个静默的账**：`solve_stage_integrated` 在窗口去相关帧数不足时**跳过**它，却
照样返回 `total_delta_G`。段1 的 w3（1000 帧去相关后只剩 5 帧）就是这么被丢掉的，
于是 86.42 是个**部分和**，跟段2 的 52.75 并排打印成"两次采样差 33.7 kJ/mol"。
现在跳过的窗口显式落 `skipped_windows` / `path_is_complete`。

## 5. 多采样段分析适配层

`multi_segment_analysis.py`（新，纯 numpy + pymbar）。

**为什么不能在 `window_outputs` 列表层面合并**：`solve_stage_integrated` 不是全局
MBAR，是「每窗口各解一次局部 TMBAR + 用共享态偏移拼接」（`global_f[lam]` 按全局 λ 态号
建字典）。同一组 `lambda_indices` 的第二条只贡献一个偏移量，**实测结果逐比特不变**，
第二段静默失效。

**做法**：保留段身份，在**最终帧集**上做一次自洽塌缩，产出一条等价的混合偏置交给现有
单采样态路径；σ 另由真正的 S+K MBAR 给出。

三条硬约束（都是踩出来的）：

* 交叉能量必须用 `sampling_states` 重建（见 §2）。
* 塌缩必须发生在帧集**定下来之后**——去相关抽帧、split-half 切半都会改变各段计数。
  用全帧解出的权重切片后不再精确（实测差 0.178 kJ/mol）。
* **数值不收敛可以降级**成各段独立分析（`analysis_mode="independent_segments_fallback"`，
  `merge_succeeded=False`），**输入错误不行**——能量错位、采样身份不一致、账本损坏必须
  继续 fail-closed，否则等于把静默错误重新埋回去。两者是不同异常类型，有 AST 测试锁住
  `except` 子句不得捕获输入错误。

**验收（真实数据，cyclod rep1 段1+段2）**：

| 窗口 | 合并 ΔF | σ（多采样态）| 双路对账差 | 合并 covESS | 帧 |
|---|---|---|---|---|---|
| w0 | 69.8300 | 0.1555 | **1.4e-14** | 390.0 | 500+500 |
| w1 | 20.8609 | 0.1254 | **4.4e-15** | 499.8 | 2000+500 |
| w2 | −8.3891 | 0.1184 | **6.7e-15** | 718.8 | 2000+500 |
| w3 | −28.1133 | 0.1641 | **8.9e-15** | 290.9 | 1000+500 |

* 塌缩是**机器精度级精确**，比要求的 1e-6 低九个数量级。
* **S=1 逐比特退化**（sd < 1e-12），现存单段窗口零回归。
* 覆盖度口径对齐：S=1 时与现有 `mixture_ess` 一致（192.92 / 289.76 / 603.19 / 261.94）。
  （这个体系里 raw ESS 与 mixture ESS 本来就重合：目标态与采样态只差逐 λ 态常数，
  在 ESS 比值里约掉。是 IBS 的固有性质，不是实现巧合。）

**端到端效果**：

```
只段1（现状）          ΔG = 84.0447   完整路径 = False   跳过 = [3]
段1+段2 合并（适配层） ΔG = 52.5539   完整路径 = True    跳过 = []
```

合并把 w3 从"被静默丢掉"救了回来。

## 6. 路径演化：插 λ 不得惊动已经算过的窗口

**bug**：插完之后把整条新路径丢给全局分窗器重新分窗。它不知道前面的窗口已经采完，
按自己的规则从头铺一遍——**21 态 `[5,5,5,5,5]` 插一个变 22 态 `[4,4,4,5,5,5]`，
窗口 0 从 5 态变成 4 态**，插在末尾却把最前面早就跑完的窗口改掉、产物全部失配。

**规则**：**已经算过的窗口必须一模一样；失败窗口往后随便怎么排都没人管**（窗口是顺序
采的，后面根本还没跑）。

**做法**：前缀逐字冻结；尾段（失败窗口起到路径末尾）**按热力学长度重新划分**。只做
下标顺延的话，剩余布局不再是热力学窗——那种布局即便结构合法也不该被接受，压住校验门
是治标。

**插几个**：目的是让压不平的窗口变**小**。只加一个态而不多划窗口，它只会更大（同一个
bias 要压平更多态）。所以按"尾段能否多划出一个窗口"定，并校验 min 的可行性
（W 个窗口共享 W−1 个边界态 ⟹ 至少需要 `min·W − (W−1)` 个态）。

真实 pilot 实测：

```
末窗失败   [5,5,5,5,5] 弧长 [2.28,2.73,3.09,3.29,2.46]
        → [5,5,5,5,4,4] 弧长 [2.28,2.73,3.09,3.29,1.20,1.26]   前缀 λ 逐个不变
中间窗失败 → 尾段两个窗被重划成三个（后面那个没采过的窗口一并重新均衡）
```

**连带修掉的门**：`_run_dual_lambda_stage` 原本"重算一份 → 要求逐字相等 → 再用重算的
覆盖调用方"，保前缀的布局必然不同所以必被拒。现在演化过的路径 / 显式分窗 / 非默认判据
声明为**权威**，改由结构判据校验（相邻只共享一个节点 + 每窗 `[min,max]` + 完整覆盖）。
默认路径逐字不变。

⚠️ **首跑的坑**：未演化时必须传 `None` 而不是 `False`——`False` 会盖掉闭包里"config
显式分窗即权威"的兜底，让 `stage2_window_ranges` 第一次跑就必被拒。

## 7. 分窗判据：等弧长 vs ∫g dλ

等**弧长**（`∫√g dλ`）均衡的是**相邻态之间的重叠**。而 IBS 是一条轨迹重加权到窗口内
**全部** K 个态，难度更接近窗口内的总方差 `∫g dλ`。经验上，**同样弧长的窗口，落在
度规尖峰上的那个 Δλ 很小、∫g 却大得多**。

> ⚠️ **这是候选指标，不是已证明的机制。** 柯西–施瓦茨 `∫g dλ ≥ L²/Δλ` 只说明两者
> 不等价，并没有证明 ∫g 预测 IBS 收敛。热力学长度有 Fisher 度规基础；`∫g dλ` 则
> **依赖 λ 的参数化方式**（变量变换下会变）。目前的证据是"换上去之后布局更好、
> 跑得通"，支持继续实验，不足以宣称收益来自这个指标。待办：把 Fisher、∫g、交换率
> 三者的预测效果放在同一批窗口上直接比较。

实测（4W53 cyclod，21 态，五个窗）：

| 窗 | λ 区间 | 弧长 | ∫g dλ |
|---|---|---|---|
| 0 | 1.0000–0.7172 | 2.28 | 19.1 |
| 1 | 0.7172–0.5102 | 2.73 | 37.3 |
| 2 | 0.5102–0.3645 | 3.09 | 67.2 |
| 3 | 0.3645–0.2520 | 3.29 | **97.0** ← 失败的就是它 |
| 4 | 0.2520–0.0000 | 2.46 | 53.9 |

弧长 2.28–3.29 大致相等，∫g 差 **5 倍**。18 态时瓶颈在端点，加到 21 态后端点被稀释，
尖峰那段反而被压成一个窗——**瓶颈搬家而不是消失**。

**卡住均衡的是 `max` 不是 `min`。** `min=4` 是一条**工程下限**，动机是窗口两端各有
一个与邻窗共享的边界态、内部只剩 K−2 个自由态。⚠️ 但共享边界态**并不意味着**这两个
态的 f_k 不能调整，所以不能仅由"内部剩 K−2 个"推出 `min=4` 是数学上的必要条件 ——
保留它作为工程下限，别当定理引用。而 `max=5` 逼着**便宜的地方
也只能用小窗**，白白多切几刀，却在贵的地方切不动：

| 布局 | 峰值 ∫g | 不均衡度 | 尺寸 |
|---|---|---|---|
| 21 态 / 5 窗 / max=5（现状，布局唯一）| **97.0** | **5.08** | `[5,5,5,5,5]` |
| 21 态 / 5 窗 / max≤8 | **74.2** | **2.36** | `[8,5,4,4,4]` |
| 21 态 / 4 窗 / max≤12 | 75.3 | **1.40** | `[10,5,4,5]` |
| 21 态 / 6 窗 / max=5 | 74.2 | 3.89 | `[5,5,4,4,4,4]` |

* 21/5/max5 **没得选**：Σsizes = 21+4 = 25 = 5×5，每窗只能 5 态，任何判据算出来都一样。
* 同样 21 个态，允许便宜的头部用一个 8 态大窗，峰值 −24%、不均衡度减半，**零额外采样**。
* `[10,5,4,5]` **只要 4 个窗**、不均衡度 1.40，比现在还少跑一个窗口。
* **74.2 是地板**：等于尖峰处一个最小 4 态窗的 ∫g。想再低只能在 λ≈0.30–0.25 那段
  **加 λ 态**，分窗解决不了。
* 贪心等弧长分窗**给不出**这些形状（它把每个窗填到 max：4/5→`[5,5,5,5,5]`、
  4/8→`[7,8,8]`、4/12→`[11,11]`）。

## 8. 配置键（全部默认关闭；不设时行为逐字不变，也不进任何指纹）

```jsonc
// 预热失败时自动插 λ 并重试
"sampling_repair_policy": "path_evolution_v1",   // 默认 non_mutating_v1
"max_path_insertions": 3,

// 加帧前用生产帧重解 f_k，另开一段采样并与原段合并
"stage2_recalibrate_f_k_on_rescue": true,        // 默认 false
"stage2_f_k_recalibration_min_shift": 0.5,       // 相邻位移阈值 kJ/mol

// 分窗：显式指定，或换判据
"stage2_window_ranges": [[0,8],[7,12],[11,15],[14,18],[17,21]],
"stage2_window_partition": "metric_integral",    // 默认 "arclength"
"stage2_n_windows": 5,                           // 可选，不设则自动选
"stage2_window_max_states": 8                    // 用大窗必须同时调高
```

**注意事项**：

* `stage2_window_ranges` 是**绝对节点下标**，绑定特定 λ 表（即特定 pilot）。换体系
  λ 表就变了，同一组索引结构上仍合法但不再是 ∫g 均衡的。要给别的体系算，用
  `abfe_preoptimizer.partition_windows_by_metric_integral(...)`，它直接吐 `[[a,b],...]`。
* **显式分窗与路径演化互斥**：显式布局是"就要测这个"，而插点会改变态数、让绝对下标
  失效。两者同时配置时钉住布局、关掉演化，并打日志说明——不静默改掉指定的实验。
* 显式**不等于免检**：结构（相邻恰好共享一个态）、完整覆盖、`[min,max]` 一条都不放过。
* `stage2_window_partition=metric_integral` 时缺 pilot 数据直接 raise，**不退回等弧长**
  （那会静默改变布局）。

## 9. 别再重新论证的事

* **ATT-27 那 881 行 overlap 变异循环不要搬回来。** 把相邻态 fixed-H overlap 当 IBS
  收敛仲裁是设计错误，烧过约一周 GPU 没产出任何 ΔG。守护测试卡死
  `_run_stage_with_overlap_autorepair` 必须以 `Return` 结尾、顶层无 `While`、< 200 行。
  路径演化按 **f_k 不收敛** 触发、放在另一个函数名下，一个 overlap 判据都没有。
* **真实 vanishing 窗口相邻共享一个状态**（边界节点在两个 ensemble 里各出现一次以对齐
  自由能参考），不是互不相交的半开区间。写夹具用 `[(0,4),(3,7),(6,11)]` 这种。
* **`insert_thermodynamic_midpoint_from_ibs_lse_failure` 硬性只收两态母窗**；
  `split_window_from_ibs_lse_failure` 允许两态子窗那是**设计精修档**的下限，生产压不齐。
  两条现成路都不接 6 态失败窗口，所以才有 `insert_lambda_in_failed_ibs_window`。
* **`apply_learning_rate_penalty` 是死代码**（零调用点，v29 删了调用方没删方法）。
  `eta_penalty == 1.0` 是普遍状态，不是"早退跳过了惩罚"的证据。
* **`allow_best_effort_warmup` 默认 False 且无任何调用方传 True**，best-effort 分支
  不可达，预算耗尽一律 raise。warmup 是 fail-closed。

## 10. 未做 / 未决

* **触发判据仍未分类。** 现在外层捕 `IBSWarmupConvergenceError` 后直接插点，没有区分
  "数据不足 / 占据塌陷早退 / 完整验证不通过 / learning 从未稳定"。而且这几个计数**没
  分开记**——早退绕过 `learning_to_validation_cycles`，所以 8 次早退 + 1 次真失败报成
  "1 次"。**这是下一步该做的第一件事**：不知道预算花在早退还是真验证上，就没法定
  "有限次学习仍无法获得稳定 f_k"这个回退条件。
* **Polyak–Ruppert 平均（A）仍未做。** 论据比一开始强：控制器每次更新只有 1.09 τ，
  平均是设计里唯一能累积多于一个独立样本的机制。但需要 brd4_l2 的对照才能定。
* **∫g 判据的收益上限约 4 倍不均衡度**（受 `min=4` 限制）。尖峰段要真变好只能加 λ 态。
* **除 §11 那一次之外，其余路径仍未在 GPU 上验证。** 特别是：路径演化的插点/拆窗、
  f_k 重标定与多段合并，在 §11 那次 run 里**都没有触发**（见该节），所以它们至今
  只有离线契约测试和落盘产物复算的证据。

### 哪些机制**没有**触发，为什么

* **路径演化：`path_current` 停在 v1，一次插点都没发生。** 这是设计如此——显式分窗
  钉住布局、关掉自动插 λ（见 §8），免得它把要测的布局改掉。
* **f_k 重标定 / 多段合并：stage2 结果里没有 `f_k_recalibration`。** stage2 在走到那个
  分支之前就 converged 了。所以 §3–§5 的机制**至今仍无真机证据**。

### 一个必须记下的误判

半程日志（production rescue round 1/2）里四个窗口全部挂在 `endpoint_uncertainty`
（1.111 / 1.117 / 1.200 / 1.220 vs 阈值 1.0），w2 还挂了 `top1%_raw_weight=0.410`。
当时据此判定"这个布局在这个体系上更差"——**错了**。补采一轮之后就过了。

**教训：rescue 中途的诊断不是终局。** 这跟 §4 那个"段 1 的 86.42 其实是缺了一个窗口
的部分和"是同一类错误：拿一个还没走完的中间量下结论。

### 仍然成立的两条

1. **它是靠生产补采（round 1，窗口 0–3 各加到 500k）才过的**，不是首跑直接过。
2. **报出来的 σ 大概率低估。** 同一份日志的 split-half：window 4 漂移 −3.043 kJ/mol =
   2.24×2σ，3/5 个窗口的 σ 该被抬高，总 σ **2.4232 → 2.9761（×1.23）**，默认未采用。

### 这次连带修掉的两个 bug（都在"权威布局"这条线上）

7. **`stage2_window_ranges` 首跑必被拒。** `_run_stage2_with_path_evolution` 显式传
   `False`，盖掉了闭包里"config 显式分窗即权威"的兜底。首跑时 `version > 1` 是 False。
   改成未演化时传 **None**。
8. **同一形状犯了第二次。** 路径演化返回后那句用 `=` 覆盖：

   ```python
   _stage2_path_evolved = bool(_cur is not None and int(_cur["version"]) > 1)   # 错
   _stage2_path_evolved = _stage2_path_evolved or bool(...)                     # 对
   ```

   路径没演化时它把标志打回 False，于是同一份布局在 stage2 主调用通过、跑完所有窗口，
   **到生产补采时被那道门拒掉**。已加 AST 测试：除首次初始化外，对该变量的赋值必须
   保留原值。

> **权威来源可以有多个（显式分窗 / 非默认判据 / 路径演化），任何一处用 `=` 而不是
> `or` 都会静默清掉其它来源。** 这是本次会话里唯一重复犯了两遍的错误形状。
