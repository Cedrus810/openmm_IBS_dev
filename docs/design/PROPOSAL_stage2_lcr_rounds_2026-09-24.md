## 2. 现状（09-24 代码）

每个窗口每一段都走同一条链（`ibs_engine.run_all_windows`）：

```
种子 f_k（pilot TI，或上一段生产帧的 MBAR）
  → 偏置爬坡 0.2→1.0
  → LEARN：占据反馈 Δf = −η·kT·log(K·p)，每轮 pairwise 步长上限 0.5–4 kT，最多 50 次（:16937）
  → VALIDATE：最后 5 批冻结帧 local MBAR，max|Δf−ΔF| < 10 kJ（:17315）
  → 复现模式：左/中/右倾斜（:18904，Δ = |学到−锚点端点差| + 2 kT）
  → 生产 250k 步
```

复现模式固定三轮：段 1 → 用段 1 的生产帧重解 f_k → 段 2 → 用段 2 的重解 → 段 3，最后合并 MBAR。
三段**串行**（每段依赖上一段），同一起点坐标。warmup 本身很贵：cmet L1 溶剂 w3 的 ledger 是
LEARN 450k + burn-in 5k + VALIDATE 100k = **555k 步**，生产才 250k。

σ：stage 2 每窗取合并 MBAR 的 `dDelta_f`，再取 split-half 膨胀 `max(σ, |漂移|/2)`（:24535）；
段间散布**没有**算（每段的 `_seg_result` 只判空就丢了，`abfe_pipeline.py:18620`）。

## 3. 新协议

### 3.1 第一轮：每窗三段，互不依赖

| 段 | f_k | 起点坐标 | 积分器种子流 |
|---|---|---|---|
| C（中） | pilot 锚点 `a` | 快照 s₀ | seg=C |
| L（左） | `a + Δ·kT·(½ − t)`，t 从 0 到 1 线性（抬首态） | 快照 s₁ | seg=L |
| R（右） | `a − Δ·kT·(½ − t)`（抬末态） | 快照 s₂ | seg=R |

- **锚点** `a` = `estimate_f_k_from_pilot_ti`（现成，`abfe_preoptimizer.py:11111`）。
- **倾斜** 复用 `repro_fk_tilt` 的形状（`ibs_engine.py:8085`），但 Δ 直接给定（默认 2 kT = 现有 `IBS_REPRO_TILT_MARGIN_KT`），不再由「学到−锚点」决定 —— 已经没有「学到」了。
  ⚠️ **倾斜必须小**：IBS 里 f_k 差 1 kT = 态权重差 e 倍。Δ=2 kT ⟹ 两端相对中心各 ±1 kT、首末权重比 e²≈7；Δ=5 kT 就是 ~150 倍，混合系综塌成单态，丢掉 IBS 的跨态增强（09-23 实测倾斜 6–7.7 kT 时单段 ESS 只剩 4.9 / 7.9）。锚点误差大的窗口**不靠加大倾斜去罩**，靠第二轮用合并 MBAR 重定中心（§3.3）。
- **没有 LEARN、没有 VALIDATE**：偏置爬坡（现有 5 档）→ 固定 burn-in（丢弃）→ 生产。
  这就是现在复现模式预热失败时走的「临时生产」路径（`debug_provisional_on_warmup_failure`），改成默认走、而且不算失败。
- **起点**：预平衡只算一次；**所有段都从预平衡末帧起跑、只换速度种子**（09-25 照 OpenFE 定，§12.9-2），与现在 `self.positions` 同一份坐标与生产盒。
- 三段互不依赖 ⟹ **可以并行**（先在进程内串行实现，接口按可并行设计）。

锚点误差（决定第二轮要不要重定中心、以及信赖域 R 取多大）：非零窗口里 pilot 锚点相对最终合并 MBAR 的误差（19:16 批，每窗 50 个腿）：

| 窗口 | 中位数 | p90 | 最大 |
|---|---|---|---|
| w0 | 0.78 kT | 1.49 | 2.08 |
| w1 | 0.85 | 1.58 | 3.01 |
| w2 | 1.09 | 2.48 | 3.11 |
| w3 | 1.10 | 4.33 | 7.95（该窗 MBAR 本身不可靠） |
| w4（含 λ=0） | 1.70 | 4.36 | 8.48 |

w0–2 中位数 ~1 kT ⟹ Δ=2 kT 的左右两段够覆盖；w3/w4 的尾部（4–8 kT）第一轮罩不住，由第二轮重定中心处理。
（这张表是窗口首末总差；§11 重放用的是逐态最大偏差，数字不同但结论一致。）

#### 3.1.1 含 λ_vdw = 0 的窗口（特殊情况）

§11 重放实测：**复合物腿**的 λ=0 窗口里，pilot 锚点在 λ=0 端**系统性偏低**
F−a 中位 **+2.77 kT**、23 个里 21 个为正（p10 +1.6、p90 +4.3）；溶剂腿同一窗口中位 −0.08，没有偏差。
LEARN 在这个窗口也好不到哪去（锚点中心和 LEARN 中心各有 10/46 个窗口某态覆盖 < 0.25）。

规则：复合物腿 λ=0 窗口的第一轮中心 = 锚点 + **末态上抬 2 kT**（线性，首态不动），再照常左/中/右各 2 kT。
重放：覆盖不足从 10/46 降到 3/46。倾斜仍是 2 kT，只是中心校正了一个**测得的**系统偏差，不是靠加大倾斜去罩。
**为什么 λ=0 特殊 —— 代码里已经写了**，两处：
- `repro_fk_tilt` 的 docstring（`ibs_engine.py:8091`）：pilot-TI 是 ⟨dU/dλ⟩ 的梯形积分，软核在 λ→0 附近 dU/dλ 很陡、pilot 点又稀，锚点在这一段最不准 ⟹ 含 λ=0 的窗口倾斜**不用锚点**。
- 独立端点模块的说明（`ibs_engine.py:~12872`）：λ→0 的态要的是「配体不与环境相互作用」下环境**进到鬼影体积里**的构型；
  从耦合结构出发的窗口混合轨迹采不到，能量判据却显示重叠「完美」（相邻 ⟨ΔU⟩ 只有 0.4–0.6 kT）⟹ 这是**构型覆盖**问题，
  加窗、插 λ、延长采样、重加权都治不了。代码给的正解是 λ≈0 的态各自跑**独立的固定-λ 轨迹**（`stage2_independent_endpoint`，~90 分钟/腿，09-01 因成本关掉）。

所以上面的「末态上抬 2 kT」只是把 f 放对位置、让占据别塌，**治不了构型覆盖**：
- 它是从一批（7 个体系、23 条复合物腿）量出来的常数，换体系要重核；
- 它能修的只是「锚点偏」这一半；「帧里根本没有那种构型」那一半要靠起点：
  **λ=0 窗口的补段起点改用在完全解耦态上平衡出来的构型**（代码里现成的 `prepare_wet_cavity_seed`，
  `ibs_engine.py:13432`：在 λ_vdw=0 上长平衡、随后喂给各端点态；它对干腔体系不强求「湿」，构造不到就如实记录），而不是 λ=1 的预平衡帧。
  这正好也是 §3.3「换起点」规则在 λ=0 窗口该用的快照来源。
  ✅ **09-24 定：临时诊断开关，不是正式选项**（`stage2_lcr_zero_window_decoupled_seed`，默认关）。只用来查清 λ=0 窗口的覆盖问题到底是不是起点构型造成的；**问题查清后整个开关连同代码删除**，不进正式协议。

第二轮对 λ=0 窗口**不投影**（pilot 在这一端本来就不可信）。

#### 3.1.2 溶剂腿：第一轮每窗只跑一段（✅ 09-25 定，数据 §11.5）

- 溶剂腿第一轮每窗**只跑中段**（中心 = 锚点、不倾斜）；σ 用**段内按时间切三块**的 jackknife 代替段间 jackknife。
- 块间 σ > σ_tol、或有态缺帧 ⟹ 补段（换种子，与复合物腿同一套规则）。
- 溶剂腿的 CONVERGED 只要求 **1 个**独立种子段（复合物腿仍要 2）。
- 理由：溶剂腿 w0–2、w4 rep 间 SD ≤ 0.9 kJ、三段 σ_jk 无一 > 1.5，锚点也准；唯一出问题的 w3（鬼影体积灌水双稳态）在同一段里真的来回换盆，切块就能抓到。
  复合物腿不能这样省：它的慢模态（口袋侧链态）在一段里不翻转，切块会漏（§11.5 表二）。

### 3.2 每轮之后：逐窗证据

所有已有段合并做 MBAR（现成的 `_load_ibs_window_outputs_merged` + `_solve_stage_with_config_gates`），
再对每个窗口取：

| 证据 | 来源 | 用途 |
|---|---|---|
| 逐态绝对 ESS、top-1% 权重 | `target_support_gate`（现成，阈值 20 / 0.35） | 缺哪一端 |
| **留一段 jackknife**：去掉第 i 段重解一次，得 ΔF₋ᵢ | 新增 | 段间是否一致、是否依赖单段 |
| σ_jk² = (n−1)/n · Σ(ΔF₋ᵢ − ΔF̄₋)² | 新增 | σ 的段间分量 |
| 去掉某段后求解失败或某态 ESS 掉到 0 | 新增 | 标记「单段依赖」 |
| 贡献过帧的不同起点数 | 新增（段元数据） | 收敛声明的前提 |

jackknife 比「每段各解一个 ΔF 再比」合适：倾斜段单独看本来就罩不住远端，逐段 ΔF 不可比；
留一段之后剩下的段仍然互补，比的是同一个估计量。

### 3.3 第二轮起：缺啥补啥（控制器唯一的动作）

纯函数 `plan_next_round(evidence, budget, round_idx) -> List[SegmentSpec]`，每窗按优先级取**第一条**命中的规则：

| 规则（按序，只看命中的第一条，决定的是**理由**） | 条件 |
|---|---|
| **缺帧** | 某态绝对 ESS < 20（含某态一帧都没有） |
| **段间不一致** | σ_jk > max(2·σ_MBAR, σ_tol)，或 top-1% > 0.35，或「单段依赖」（去掉某段就解不出来） |
| — | 都不命中 ⟹ 该窗完成，不再补 |

命中任一条，**补的动作都一样**（✅ 09-25 定，数据见 §11.3）：
- **不倾斜**。倾斜只在第一轮用 —— 那时不知道锚点往哪边偏，左右各押一段；第二轮已经有合并 MBAR 的 F_k，中心放对了再倾斜就是故意推偏。
- **中心 = 合并 MBAR 的 F_k**；证据弱（最小逐态 ESS < 50）且不含 λ=0 时投影回 pilot ± R（§3.5）。
- **换一个没用过的起点**。
- 段长与第一轮相同（§12.9-1）。

~~旧规则：缺端 ⟹ 按缺的态在前半/后半做线性倾斜~~ —— 已否：线性倾斜对中间态几乎无效（偏移 Δ·(½ − t_k)，t_k≈½ 时≈0），
而且重放里它把另一端压塌，并集最差态 < 0.5 的比例 58%，只重定中心是 35%（§11.3）。

**病因诊断（09-25 修订）**：缺帧的窗口先看第一轮左/中/右三段各自对缺帧态贡献的 ESS：
- **一边高一边低** ⟹ f 放偏了 ⟹ 补段（重定中心；合并 F_k 已定量包含往哪挪、挪多少）。
- **三段都低** ⟹ 原因**分不清**，至少三种：① f 偏得远超倾斜的 ±1 kT（w3/w4 尾部 4–8 kT）；② 构型慢模态 / 困盆（该态要的构型从哪个起点都没采到）；③ λ 间距真的太大。
  拿生产帧算的「相邻重叠」分不开 ② 和 ③（困盆也表现为重叠小）；能单独指向 ③ 的只有 **pilot 边长**（pilot 在每个 λ 上独立采样，不受困盆影响）。
  ⟹ **动作与其它补段相同**：重定中心（修 ①）+ 换新起点（对 ② 唯一可能有用）。补到上限仍三段都低 ⟹ 标 `SAMPLING_LIMITED_CAUSE_UNRESOLVED`，
  账本同时记 pilot 窗内最长边与帧上相邻重叠，交给人判断。
- 段间不一致（σ_jk 大）⟹ 补段（换起点是关键）。

**插 λ（model B）：预案，暂不自动执行**（✅ 09-25 定）。原先写的「三段都低 + 重叠小 ⟹ 插 λ」推得太快：② 与 ③ 靠帧上重叠分不开，
而 ② 插 λ 没用（代码注释 `ibs_engine.py:~12872`：「加窗、插 λ、延长采样、重加权都治不了」）；两种情形在 19:16 批都没有样本。
等真遇到一个样本、看清是哪种原因，再定触发条件（至少要 pilot 边长也长）。届时的做法照原控制器方案 `archive/PLAN_PATH_REPAIR_2026-09-11.md` §3ter：
- 在最差的相邻对中间插一个 λ；插入点之前的窗口不动，之后的窗口 λ 内容依次左移一格、态数不变，多出来的态落到末窗；
  末窗到可拆区间 [2·lo−1, 2·hi−1] 就拆（`_legalize_tail_window`）；拆完再要插 ⟹ `HALT_LAMBDA_BUDGET_INSUFFICIENT`；插点数超过末窗能吸收的量 ⟹ 同样报错、不封顶。
- 时机：第一轮按窗口顺序跑，某窗三段跑完即判、当场插 ⟹ 下游还没采、零成本，只重跑本窗三段；第二、三轮没有左中右对照 ⟹ 不插。每窗最多插 1 次。
- ~~方案乙：采样前按 pilot 边长插~~ —— 暂不做：没有重叠不足的样本可标 pilot 阈值；真遇到了再用那些样本标定。
- 复用现成：`insert_lambda_in_failed_ibs_window`（`abfe_preoptimizer.py:10332`）、`_legalize_tail_window`（`abfe_pipeline.py:14315`）、`lambda_path_versions`。
- 每窗最多插 1 次；还不行就标出来交给人。

`SegmentSpec` = (窗口, 中心 f 及来源, 倾斜符号, Δ, 起点 id, 种子流 id, 步数)；第二轮起倾斜符号恒为 0。
每窗每轮最多补 1 段；总轮数上限默认 3（含第一轮）。

### 3.4 停止规则与结果标签

- 没有要补的段，或轮数/步数预算用完 ⟹ 停。
- 每窗打标签：
  - `CONVERGED`：各态 ESS ≥ 20、top-1% ≤ 0.35、σ_jk 可算且 ≤ σ_tol、**至少 2 个不同起点**贡献了帧。
  - `PROVISIONAL`：有数，但以上任一条不满足。
  - `INDETERMINATE`：某态一帧可用的都没有（沿用现有 `_collect_indeterminate`）。
- 预算用完仍不 `CONVERGED` **不抛异常**，按标签进 `results_untrusted`。

### 3.5 f_k 信赖域（第 1 条的剩余部分）

第一轮中心就是锚点，天然在域内。第二轮用合并 MBAR 重定中心时，**只有该窗合并证据弱（最小逐态 ESS < 50）才投影**：
把逐态累计偏移 `(f_k − f_0)` 投影回 `(a_k − a_0) ± R`，保持 f 的均值不变。
证据强的窗口直接用 MBAR 的 f —— 这时 MBAR 比 pilot 准，§11 里 cyclod outer rep1 溶剂 w1（ESS 896、偏锚点 5.7 kT）
若无条件投影，会把一个测准了的窗口压到最小覆盖 0.23。

- R = max(`R_floor`·kT, 3·σ_pilot,k)，σ_pilot 由 pilot 的 std/√n 按梯形规则传播；`R_floor` 默认 3 kT。R 不是倾斜，只挡「追飞」（那些窗口偏离锚点 8–24 kT）。⚠️ w0–2 锚点误差最大 3.1 kT，刚好压线 —— 真值偏出 R 时被投影回来，代价是那一段占据偏 e^(误差−R) 倍。
- 含 λ_vdw = 0 的窗口**不投影**（与现有倾斜同一理由：pilot 在 λ→0 最不准，实测偏 5–8.5 kT）。
- 安全性：f_k 只影响采样效率，ΔG 由 MBAR 扣掉偏置 ⟹ 约束错了最多是采样变差，答案不会错。

### 3.6 σ

每窗 σ_window = max(σ_MBAR合并, σ_jk, split-half 膨胀值)；总 σ 仍按窗口平方和（`ibs_engine.py:23859`）。

```
    if 三段 ESS 都低 且 相邻重叠小 且 w 还没插过:
        插 λ（model B）→ 新布局落盘（lambda_path_versions）→ 按新 λ 内容重跑 w 的三段   # 下游还没采，零成本
while True:                                                          # 第 2 轮起
    r = ledger.最新一轮
    执行 ledger 里第 r 轮所有 PLANNED 的段 → 逐段标 SAMPLED / FAILED     # 12.4
    merged  = 全部 SAMPLED 段的合并求解（逐窗；现成的 _load_ibs_window_outputs_merged + _solve_stage_with_config_gates）
    evid    = 逐窗证据（含留一段 jackknife，12.3）
    labels  = classify_window(...)
    ledger.record(round=r, evidence=evid, labels=labels, result=merged)   # 每轮都落
    specs   = plan_next_round(evid, completed_round=r, used_start_ids=ledger.用过的起点)
    specs   = 预算裁剪(specs)                                            # 12.5
    if not specs: break
    ledger.plan(round=r+1, specs)
收尾：最后一轮的 merged 即 stage 2 结果（12.6）
```

两条硬规矩：
- **先落账、再采样**：一轮的段一旦 PLANNED 就冻结，resume 时照账执行，**不重新计划**。
  否则半截写盘的段会改变证据 → 重新计划出不同的段 → 同一轮被采两套（这正是 4W53 resume 反复重跑那一类「执行历史混进身份」的形状）。
- **每轮都完整落账**（证据 + 标签 + 当轮合并结果），任何一轮之后中断都能从账本恢复到同一个状态。

### 12.2 段怎么组织

- **第 1 轮 = 3 个段，每段覆盖全部窗口**：段 1 = 中（起点 0 = 预平衡末帧，与现在一样）、段 2 = 左（起点 1）、段 3 = 右（起点 2）。
  一段内所有窗口同一个倾斜符号、同一个起点帧。**执行顺序按窗口**（09-25）：w 的中/左/右三段跑完 → 判是否插 λ → 下一个窗口；三个段目录随窗口逐步填满。
- **第 2 轮起 = 每轮 1 个段，只含被点名的窗口**（部分段；合并 loader 已支持逐段声明缺窗）。
  同一段里不同窗口的中心 f_k、起点可以不同（倾斜 09-25 起恒为 0）⟹ 引擎要能**逐窗**给 f_k 和起点坐标（12.4）。
- 目录沿用 `{stage}_{N}` / `checkpoints/segment_{N}`；每段落 `segment_spec.json`（逐窗：中心 f_k、中心来源、倾斜、起点 id、种子流、计划理由、所属轮）。
- 下一段编号只在账本里分配一处（现在 `max(existing)+1` 散在三处）。

### 12.3 逐窗证据怎么算

- 合并 MBAR（全部 SAMPLED 段）→ 逐态 ESS、top-1% 权重、σ_MBAR、逐态 F_k、窗口 ΔF。
- 留一段：该窗有 n 段就重解 n 次（每次去掉一段）；去掉后某态没有帧或求解失败 ⟹ 记 nan（= 单段依赖）。只对该窗有 ≥2 段时算。
- `n_distinct_starts` 从账本的段 spec 读，不从盘上猜。
- 锚点与信赖域半径：pilot 数据 → `estimate_f_k_from_pilot_ti` + `pilot_trust_radius_kJ`，每窗算一次存进账本。

### 12.4 执行一段（引擎要新增的入口）

`run_all_windows` 现有 `initial_f_k_by_window` 只是 warmup 种子（之后照样 LEARN）。新增：
- `fixed_f_k_by_window`：给了就**跳过 LEARN / VALIDATE**，爬坡 → 固定 burn-in（丢弃）→ 生产；f_k 原样用（倾斜已在 spec 里算好）。
- `start_positions_by_window`：逐窗起点坐标（已缩放到生产盒）。
- 段种子流：`_seed_for` 的流名里带段号（现在不带，段间可能同种子）。
- 一段里某个窗口崩了（NaN / 模拟失败）：该窗在这段标 FAILED，其余窗口照常；这个窗口下一轮的证据里自然少一段，规则照走。

### 12.5 预算

- 轮数上限 3（含第 1 轮）⟹ 每窗最多补 2 段。
- 全局步数上限 `stage2_production_budget_steps`（没设 = 不限）：本轮 specs 超出时按优先级裁剪 —— **待定**（12.8 第 2 条）。
- 被裁掉的窗口不报错，标签照实（多半是 PROVISIONAL），进 `results_untrusted`。

### 12.6 输出

- ΔG = 最后一轮合并求解的 ΔG。
- σ = 逐窗 `sigma_window_kJ`（max(σ_MBAR, σ_jk, split-half)）的平方和开方。
- 逐窗标签 + 理由；任一窗不是 CONVERGED ⟹ `results_untrusted=True`；INDETERMINATE 窗口沿用 `_finalize_with_indeterminate`（ΔG 剥掉、`ANALYSIS_INCOMPLETE`）。
- `analysis_mode="stage2_rounds_v1"`，结果里带账本路径和每轮摘要。
- **不抛异常**的只有「采样证据不够」这一类；输入 / 身份 / 账本不自洽照旧 fail-closed。

### 11.3 第二轮补段该怎么放 f_k（09-25，19:16 批）

**问题**：某态缺帧（尤其中间态、两端都缺）时，第二轮新段用什么 f_k。
**测法**：每窗只用三段里的两段估 F（模拟「第一轮数据有限、缺帧态的 F 估不准」），以此为第二轮中心；用三段全部的 F 当真值算新段占据。
判据看**并集**（已有两段 + 新段，每态取最好）的最差态 —— 最终合并 MBAR 用的是全部帧，要紧的是这个。
样本：7 个体系（排除 outer 与 cyclod_ligand2）里有态 ESS < 20 的 31 个情形。

| 第二轮新段 | 并集最差态中位 | < 0.5 | 其中缺中间态（16） | 其中只缺端态（15） |
|---|---|---|---|---|
| 线性倾斜（旧规则） | 0.42 | 58% | 69% | 47% |
| **只重定中心** | **0.63** | **35%** | **56%** | **13%** |
| 抬缺帧态 δ = ln(20/ESS)，≤ 2 kT | 0.52 | 48% | 69% | 27% |
| 抬缺帧态固定 1 kT | 0.47 | 58% | 69% | 47% |

- 线性倾斜把缺帧的一端抬上去（新段里缺帧态占据中位 2.8），但把另一端压塌。
- 单独抬缺帧态能把缺帧态本身补得最好（固定 1 kT：新段里缺帧态中位 1.56），但压低其它态，按并集算不如只重定中心。
- 只重定中心够用的原因：缺帧态的 F 合并 MBAR 也只估偏一点（新段里缺帧态占据中位 0.83），中心放到 F 上占据基本就平了。

**局限**：31 个情形；「第一轮」用的是现协议的段（LEARN 学出来的 f），不是新协议的锚点 ± 倾斜。新协议第一批出来后重核。

补测（09-25）：**「复制缺帧态 ESS 最多的那一段的 f」**（第一轮左中右里哪段对缺帧态贡献的有效样本最多，就照它再采一段）——
新段里缺帧态占据中位 **0.00**（97% < 0.5），并集最差态中位 0.02；只重定中心分别是 0.83 / 0.63。
原因：合并 ESS < 20 意味着**每一段**对这个态都不够，照最好的那段再采一次只是把一个不够的分布再复制一遍；
合并 MBAR 的 F_k 用了全部段的信息，直接把中心放到这个态该在的位置。
⚠️ 这批段的 f 是 LEARN 学出来的（有的已追飞），比新协议的锚点 ± 2 kT 偏得远，所以 0.00 夸大了差距；但「复制一个已知不够的段」在道理上就比不过重定中心。

#### C. 身份（B9 引出，⚠️ 更正 PLAN §4 原来的写法）

PLAN §4 原来写「新增配置键 `stage2_lcr_*` 全部进 stage 指纹」—— **这是错的**，正是 09-11「阈值键进 `stage_protocol_key`、改 config 作废全部窗口缓存」那次事故的形状。

多段 MBAR 对**任何** f_k 采的段都成立（每段按自己记录的 f_k 进交叉能量）。所以一段帧是否可用，只取决于**哈密顿量和布局**（现有 stage 身份），与它当初按什么规则计划出来无关。
⟹ ✅ 09-25 定：`stage2_lcr_*`（倾斜、上抬、信赖域、σ_tol、轮数、burn-in、起点规则）**全部是计划参数，不进身份**，加进 `_NON_IDENTITY_KWARGS`；
每段实际用的值记在它自己的 `segment_spec.json`（执行历史），账本记每轮计划时用的阈值。
