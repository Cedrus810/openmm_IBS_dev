## 1. R1 到底要产出什么

计划 §8 的 R1 交付物是「映射和受限 hybrid builder」，验收标准是
「映射可审计；端点相互作用及 dummy 处理有验证；有限差分力与解析力一致」。

拆开就是两件事，本文只讨论**第一件**：

1. **原子映射**：给出 A→B 的一一对应，并划出 common core / A-only / B-only 三组原子。
2. hybrid builder：按这个划分构建逐 λ 的 Hamiltonian。（另议）

计划 §5.2 对映射的硬要求：

- 分子内索引、complex 全局索引、solvent 全局索引、hybrid 索引**分别**记录；
- 验证一对一、索引范围、化学一致性、**映射核心的连通性**；
- 识别对称等价映射与姿势歧义；
- 两腿使用**同一份冻结**的分子级 A→B 映射，再各自投影为全局原子索引；
- 映射评分只用于候选排序，**不能代替**化学与几何验收。

## 2. 仓库里已有什么（已核对）

用户提到的「二面角那堆代码」确实可用，而且比预期的好。核心是
`outer_lambda_neural_basis.py::discover_ligand_rotatable_torsions`（`:5627`）。

### 2.1 可直接复用的四块

| 块 | 位置 | 对 R1 的用处 |
|---|---|---|
| 从 topology bonds 建**限定在配体内**的邻接图 | `:5646-5648` | 映射器要的分子图，现成 |
| `central_bond_is_in_ring()` | `:5655-5668` | 环成员判定（走图找替代通路）。计划 §2 拒绝的**环断裂/闭合、环尺寸变化**正是靠它才检得出来——R0 目前把这几项列在 `ValidationReport.unchecked` 里，就是在等这个 |
| 重原子过滤 + `outer_priority` 确定性选点 | `:5651`、`:5690` | §5.2 要求识别对称等价映射，需要一个**确定性的规范选择**，这个模式直接可用 |
| `_atom_identity()` / `stable_id` | `:5603` | §5.2 要求多套索引分别记录；这是一套「跨 System 重建仍可审计」的原子身份（chain/residue/name/ordinal/element） |

### 2.2 关键性质：这一套不需要 rdkit

`discover_ligand_rotatable_torsions` 直接吃 **OpenMM topology 的键图**，
不做任何化学感知。这带来一个计划 §5.1 明确在意的好处：

> **不能为了调用第三方 builder 悄悄把当前力场重参数化。**

首版锁定的输入是**已参数化的 GROMACS／OpenMM 输入**。在 topology 图上做映射，
意味着全程不离开用户给的那份参数——不重新感知键级、不重新分配电荷、不重新
参数化。而任何「转成 rdkit Mol 再映射」的路线，都要先做一次化学感知，
感知结果和原始参数化不一致时，错误会静默地进到映射里。

### 2.3 不要用的那份

`abfe_core.py::get_rotatable_torsions_rdkit`（`:9378`）**不建议用于 R1**：
它的 SMARTS `[!#1;!D1]-[!#1;!D1]` **不排除环键**，拿来切分子会把环切开。
它服务的是扭转扫描，不是图分解。

### 2.4 确实不存在的

全仓 `grep -rniE "atom_map|MCS|maximum_common|hybrid_topology|dummy_atom"` 对生产模块
零命中。**没有原子映射器，没有 hybrid builder。** 第三方也没有：`openfe` / `perses` /
`openff.toolkit` / `kartograf` 在 `openmm_dev` 里全部未安装（`rdkit 2026.03.5` 已装）。

计划 §5.2 另有一条提醒，核对过属实：现有教师／student 的原子映射**不是** alchemical
atom mapper，不能因为名字像就拿来用。

## 3. 三条候选路线

### 路线 A：片段级映射（本提案倾向）

在**非环可旋转键**处切开 A 和 B，得到片段集合，先做**片段级**匹配，
再在匹配上的片段内部做原子级对齐。

优点：

- 片段数是个位数，匹配结果**人眼能审、能落盘复核**——直接满足「映射可审计」；
- 首版范围（同骨架、无环变化、中性）下，公共核心大概率就是共享的环系+连接子，
  差异集中在末端支链——正好是这套分解会浮出来的结构；
- 图论部分（§2.1 四块）已经存在且被现有测试覆盖，新代码只有匹配层；
- 全程在 topology 图上，不重参数化（§2.2）。

缺点／未知：

- 片段边界由「可旋转键」定义，A 和 B 的可旋转键集合不同时，切法可能不对齐——
  **这是本路线最大的未验证点**，需要先在真实配体对上试过才能定；
- 片段内部仍需原子级对齐（可以是小规模 MCS，也可以是按元素+连通性的确定性遍历）。

### 路线 B：原子级 MCS（rdkit `rdFMCS`）

优点：成熟、一步到位、rdkit 已装。
缺点：需要把 topology 转成 rdkit Mol（化学感知，见 §2.2 的风险）；对称结构上会给出
多个等价解，仍要另写消歧；MCS 结果是原子集合，不天然给出 common core 的连通性验证。

### 路线 C：封装第三方（OpenFE / Perses）

优点：最省事。
缺点：均未安装，引入一大坨依赖链；计划 §5.3 已记录 OpenFE 官方文档自己提醒某些
dummy bonded 处理存在**不抵消导致系统误差**的风险；且它们默认自带参数化路径，
与 §5.1「不得悄悄重参数化」冲突，需要额外把那部分关掉并验证。

### 混合路线 A+B（可能是实际答案）

片段分解定骨架对应关系（A），片段内部用小规模 MCS 对齐（B）。
把 MCS 限制在已配对的片段内，既避免了全分子对称歧义，又不必自己写图同构。
rdkit 只在「片段内对齐」这一步用到，且用完即弃，不参与建系。

## 4. 如果走 A（或 A+B），具体分几步

| 步 | 内容 | 依赖 |
|---|---|---|
| M0 | 从两个端点的 topology 各自建配体子图（复用 §2.1 第 1 块） | 无 |
| M1 | 标注环成员（复用 `central_bond_is_in_ring`），**并据此实现 R0 目前 `unchecked` 的环相关拒绝** | 无 |
| M2 | 在非环可旋转键处切分，得到片段集合 + 片段连接图 | 无 |
| M3 | 片段级匹配：按元素组成、大小、连接拓扑配对；产出候选排序 | 无 |
| M4 | 片段内原子级对齐（自写确定性遍历 或 rdkit MCS） | 可选 rdkit |
| M5 | 组装 `AtomMapping`：分子内 / complex 全局 / solvent 全局索引分别记录，冻结并落 `atom_mapping.json` | 无 |
| M6 | 映射验证：一对一、索引范围、化学一致性、**core 连通性**、对称等价解检测 | 无 |

M1 有个附带收益：R0 的 `ValidationReport.unchecked` 里现在挂着六条
「需要原子映射，R1」——环断裂/闭合、环尺寸变化、手性反转、映射元素改变、共价配体、
互变异构。M1/M6 做完，其中环相关和元素改变这两类就能从 `unchecked` 移到真正的拒绝判据。

编排层已经预留好接口：`rbfe_pipeline.edge_identity()` 有 `atom_mapping_hash` 参数，
映射一旦冻结就进边身份指纹，换映射自动拒绝复用旧产物（§7 要求）。

## 5. 需要你决定的

1. **走哪条路线**：A / B / C / A+B。
2. **rdkit 用到什么程度**：完全不用（纯 topology 图）、只在 M4 用、还是全程用。
   影响的是「会不会引入一次化学感知」这个风险面。
3. **第一对真实配体是什么**——这一条不解决，R1 做完也没法验证。
   计划 §8 原话：不能根据 Atenolol 文件名猜测 B，也不能把接口测试当作真实体系验证。
   需要你提供配体 B 的结构／参数，或指定一对公开基准配体。
