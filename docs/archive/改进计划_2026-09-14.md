## 2. 重复实现

### 2.1 `calc_angle` 四份 —— **不是「一对三错」，是三种不同契约**

【实测】四处及其调用点：

| | 位置 / 外层 | 单位 | 判定 |
|---|---|---|---|
| **A** | `abfe_core.py:9086` ← `OrbBoreschEstimator._check_anchor_geometry` | 度 | **正确**。消费方是 `30 <= angle_P <= 150` 和 `cfg["rec_anchor_angle_min/max"]`，全是度。锚点**打分启发式**，不进哈密顿量。 |
| **B** | `abfe_core.py:9613` ← `OrbBoreschEstimator.estimate_from_trajectory` | 弧度 | **正确**。写进 `eq["thetaA0"]` 喂 OpenMM Boresch，OpenMM 角度就是弧度。 |
| **C** | `abfe_core.py:9669` ← `OrbBoreschEstimator._finalize_candidate` | 弧度 | **冗余**。与 B 同数学、同单位、同消费方，**同一个类、相隔 56 行**，只是改名 `calc_angle_rad`。 |
| **D** | `ibs_engine.py:23376` ← `_check_boresch_geometry_safe` | 弧度 + NaN | **正确**，契约不同：它是**安全检查器**，NaN 是"不安全"信号，**下一行就被 `np.isfinite` 消费**并 `return False`（fail-closed）。 |

#### ❌ 不要做的修法

**不要把四份合成一个共享 helper。** D 的 `denom<=1e-12 → NaN` 只有在
"调用方紧接着查 `isfinite`" 时才对。B/C 的调用方**不查**——它们直接把值写进
Boresch `eq` JSON。把 D 的 NaN 语义推广过去，等于**把 NaN 静默写进约束参数**，
比现状更糟。A 的"度"也不是错，是它的消费方就用度。

#### ✅ 真正该做的两件小事

1. **合 C 进 B。** 不只角度——`estimate_from_trajectory` 和 `_finalize_candidate`
   里那个 `eq` dict 的**六个键各写了一遍**（`r0`/`thetaA0`/`thetaB0`/`phiA0`/`phiB0`/`phiC0`）。
   该抽的是构 `eq` 的那一段，不是角度函数。
2. **给 A 改名**（如 `_anchor_angle_deg`）。同一文件里两个 `calc_angle` 返回不同单位，
   各自正确但对下一个改代码的人是陷阱。**改名，不要合并。**

#### 关于 `+1e-10`（初版说重了）

四处输入都是**三个不同的原子**（受体锚点 / Boresch 锚点），范数恒 ≥ 约 0.1 nm，
`1e-10` 的相对量级 1e-9。退化情形在这些调用点构造不出来。
**是味道，不是 bug。**初版称其 "fail-open" 是夸大。

#### 与 BOR-01 的关系

`docs/TODO.md:25` 记的规矩是「**同一个不变量只能有一份实现**」。
【实测】二面角**已经**照办：`abfe_core.py:8676 boresch_dihedral_rad` 是模块级单源，
`tests/test_boresch_dihedral_convention.py` 拿 OpenMM `dihedral()` 和 mdtraj 双向钉死。
键角没跟上——但如上所述，键角的正解是**"消除 C 这一份冗余"**，
不是"也造一个单源函数"，因为它有三种真实不同的契约。
