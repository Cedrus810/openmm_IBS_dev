# 核心计算准确性复查（2026-10-03）

## 结论与证据范围

当前实现仍有会影响结果可信度的缺口，优先级最高的是 **LCR 旧段复用的协议校验**，以及
**多段全部困在同一个构象盆地时，现有收敛标签不能识别漏采**。其次是固定 f_k 的 burn-in
实际时长、补采中心的采样规范、盒体积校验的调用缺口。接力还存在独立性统计问题。

本轮没有确认默认 soluble / 非共价 / dual_lambda 路径存在新的热力学循环符号、单位、
Boresch 解析公式或 MBAR 代数错误。这个结论仅限本轮检查和测试，不能解释真实体系的
全部偏差，也不能从中推导“剩下只能是力场”。

范围：读取当前工作树，保留已有未提交改动；核查 `abfe_core.py`、`ibs_engine.py`、
`abfe_pipeline.py`、`runabfe.py` 相关生产调用链，以及 `stage2_rounds*` / `multi_segment_analysis`。
检查旧审核条目时重新定位当前源码，不把旧报告结论当成本轮证据。
RBFE、暂停的膜线、非默认 neural-residual/DEXP 路线没有作完整审计。
没有重跑真实蛋白 MD、没有读取外部 benchmark 数组、没有量化真实体系的误差归因。

复现脚本：[core_accuracy_2026_10_03.py](../../tools/audit/core_accuracy_2026_10_03.py)。
它只在临时目录生成合成产物，退出时删除；不修改生产输入或缓存。

## 1. P1：LCR 账本未绑定阶段协议，换协议后旧段仍被复用

**当前代码确认；假采样器复现了执行层与证据层行为。** 此问题在 09-26 审核出现过，目前仍在。

- `abfe_pipeline.py:14740` `_stage2_rounds_ledger_load` 只比较版本与 λ / 分窗布局。
- `abfe_pipeline.py:14877` 开始的执行循环遇到 `SAMPLED` / `FAILED` 就跳过。
- 已有本轮 `evidence` 时不会重新求解。
- `abfe_pipeline.py:15531` 的合并加载没有向底层传当前 `expected_window_protocol`。
  文件哈希、冻结 f_k、段内 manifest 的自洽性检查，不能代替“与本次协议一致”的检查。

复现：先用 kT=2.494 kJ/mol 执行第一轮，共 9 次假引擎调用；保持 λ 布局，改成
kT=2.9928 kJ/mol 再调用真实 `_run_stage2_rounds`。新增引擎调用为 **0**，旧证据原样复用。
复现没有执行最终真实 MD 合并，不能把它描述成真实 benchmark 温度修改实验。

实际触发条件：复用输出目录，温度、Boresch、softcore、接力协议等身份变了而 λ 布局没变。
上层 stage 缓存失配后仍可能进入这个漏洞，把旧产物归入当前协议。

修复方向：账本绑定当前阶段采样协议及已提交生产盒身份；读取 SAMPLED 段时校验本次身份；
合并 loader 接入相同的期望协议。身份变化时拒绝混用，不通过重新贴当前指纹来“升级”旧段。
固定预算的改变也应校验已完成步数，不能只沿用 `SAMPLED` 标志。

## 2. 科学准确性风险：共同漏采的构象盆地可以带着 CONVERGED 标签通过

**数值反例已复现；这是收敛证据的覆盖限制，不是 MBAR 公式错误。**

位置：`stage2_rounds_evidence.py:90` 与 `stage2_rounds.py:275`；执行层把贡献过帧的段数
作为 `n_independent_seeds`。标签检查 ESS、top-1% 权重、留一段差异及种子数，无法知道
所有段共同遗漏的构象区域。

精确双盆模型：两态在盆 A 的能量均为 0；盆 B 的两态能量分别为 0 和 −8 kT。
三段各 400 帧全部困在 A，真实项目函数给出：

| 量 | 返回值 |
|---|---:|
| 状态标签 | CONVERGED |
| 逐态 ESS | 1200、1200 |
| jackknife σ | 0 kJ/mol |
| 估计 ΔF | 0 kJ/mol |
| 精确双盆 ΔF | −18.224127435 kJ/mol |

精确值来自 `−kT ln[(1+exp(8))/2]`。上述差值是合成模型的结果，**不能作为 HSP90
或任何真实体系的误差估计**。它证明高 ESS、小 σ、不同速度种子均不充分证明构象平衡。
ESS 此处主要反映观测帧的权重集中程度；本证据层明确使用全部帧，并未扣除时间相关。

改进方向：在实际出现慢模态的窗口记录构象盆地占据与转换、逐段 ΔF / 结构漂移；
采用有代表性的不同构象起点，比较足够长的连续采样或可跨盆的增强采样。
不能靠调小 ESS 阈值或增加相同起点的短段来宣称这个问题解决。
建议把当前标签的物理解释限定为“现有观测数据通过所列判据”，保留构象覆盖未验证状态。

## 3. P2：固定 f_k burn-in 时长与配置说明不一致

**源码控制流确认；没有运行完整窗口 MD 来测量此项的 ΔG 影响。** 09-30 审核已登记，仍在。

- `ibs_engine.py:16404` 新窗口的 bias ramp 把步长设为 0.001 ps。
- `ibs_engine.py:16970` 的固定 f_k burn-in 沿用该步长。
- 直到 `ibs_engine.py:19015` 才恢复生产步长。

因此正常新窗口的默认 25000 步 burn-in 是 **25 ps**；注释/设计中按 2 fs 解释的
“50 ps”不成立。5000 步的诊断块是 5 ps。成功恢复 IBS 状态的分支跳过 ramp，
burn-in 可能处在 2 fs 下；两条路径的物理时长不同。测试步进降为 1 fs 的异常路径另当别论。

另有独立的取整问题：`max(1, ceil(total/block))` 每块执行完整 `_block` 步。
在 5000 步分块下，7000→10000，1000→5000，0→5000；默认 25000 恰好整除。

后果是平衡量的解释与实际不符，可能保留更多起跑瞬态或额外消耗预算。
没有证据支持“修正时长就一定能解决蛋白慢模态”。
修复方向：明确 ramp / burn-in 的步长契约与物理时长；resume 用相同约定；
最后一块按剩余步数执行，明确定义零步和负值行为。

## 4. P2：补采 f_k 中心混入分析侧的逐态 LJ 尾项

**真实数值函数复现；影响采样分配，单独不能证明 ΔG 算错。** 09-30 审核已登记，仍在。

`stage2_rounds_evidence.py:51` 用目标能量（含 LJ 尾项）求得 `merged_f_k_kJ`；
`stage2_rounds.py:319` `_next_center` 直接把它当作后续采样中心。
实际 IBS 混合使用的是 `sampling_states`，尾项常数不在那个采样势里。

合成复现：保持所有采样帧与固定偏置不变，仅给第二目标态加 3 kJ/mol 常数。
下一轮中心相对采样口径多出 `[0, 3]` kJ/mol；在 kT=2.494 时，理想平衡成员
占据的相对倍率变成 `exp(3/2.494)=3.329715712`。
这不是本轮对真实蛋白占据倍率的测量。

多段交叉偏置仍由采样能量重建，正确重加权原则未被这项破坏；风险是有限预算下某些态
采样不足，且信赖域与 pilot 锚点不再处于同一规范。
修复方向：为补采中心另解采样规范 F_k；目标规范保留给 ΔG 与其权重统计。

## 6. 条件性问题：接力段仍按独立种子段计数

**源码确认；仅 `stage2_lcr_relay=true` 时触发，该开关默认关闭。**

`abfe_pipeline.py:14893` 开始选择前段末态起跑，`abfe_pipeline.py:14976` 仍将段数传为
`n_independent_seeds`；jackknife 继续按段做。随机速度不同不消除前段构象状态的继承，
不能把连续接力的三个短段当成三条独立构象证据。

开关旁的注释已承认 jackknife 可能乐观，但执行层与标签没有调整。
应记录接力链身份，按独立链而非段计数，并用适合连续数据的块统计评估误差。
未验证前应继续保留关闭状态。本轮没有重新验证交接里“接力造成 26 kJ 位移”的真机数字，
也没有证明这个统计问题是该位移的原因。

## 7. 条件性问题：不完整路径的 jackknife σ 可能配错物理窗口

**源码确认；正常全窗成功时不触发。** 09-26 审核已登记，仍在。

`ibs_engine.py:23991` 的协方差链同时保存局部 `window_index` 与真实 `source_window_index`。
`abfe_pipeline.py:15068` finalize 按局部编号建表，再按真实窗口号取值。
如果前面的窗口在去相关后被跳过，σ 对应关系错位，后面的窗口可能遗漏 jackknife 增量。
该情形原本是 `ANALYSIS_INCOMPLETE`，不能夸大成已经通过完整可信结果门。
应使用已有 `_segment_physical_window` 语义或 `source_window_index`，保持不完整状态。
