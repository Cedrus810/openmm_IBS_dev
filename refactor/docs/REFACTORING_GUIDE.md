# 重构作业指导书

**给接手这项重构的 agent。本文是「怎么下刀」，不是「切什么」。**

四份文档的分工，别混：

| 文档 | 回答 |
|---|---|
| `HOW_TO_CONTINUE.md` | 路线（A→B→C）与**授权边界** |
| `CUTTING_PLAN.md` | 切什么、切哪里、为什么是那个刀口 |
| `work/PROGRESS.md` | 现在到哪了、下一刀是什么 |
| **本文** | **怎么切才不出事** |

---

## 一、四条铁律

### 1. 写操作只在 `refactor/` 目录内

主线（`abfe_core.py` / `ibs_engine.py` / `abfe_pipeline.py` / `abfe_preoptimizer.py` /
`runabfe.py` / `tests/` / `docs/`）**只读，作对照**——核对拆出来的东西对不对。

「在主线切一下顺便跑测试验证」这种方案**连提都不要提**。
`refactor/` 本来就跑不起来（缺 import、无 `__init__.py`），验证手段是 AST 等价，
不是跑测试。这不是妥协，是这项工作的前提。

### 2. 没有门的刀不开

每一种变换先确认它**有对应的机械门**，再动手。没有门就先造门，
造完**自检**（见三、门的自检），自检过了才敢用它验真刀。

### 3. 没有留底的刀不开

```bash
cp <目标文件> refactor/work/<刀名>.before.py
```

执行器**不自带留底**，留底是你的事。留底同时是门的 `before` 输入，
也是唯一的回滚路径。

### 4. 纯搬运与改行为，绝不同刀

混在一起出事就没法二分定位。这是本仓最贵的教训的形状。

## 二、三种变换 × 三种门

下刀前先判断这刀属于哪一类。**判错类型 = 用错门 = 门形同虚设。**

| 类型 | 做什么 | 门 | 状态 |
|---|---|---|---|
| **A 纯搬运** | 块整体移位；名字引用不变 | `verify_extract.py` | ✅ 可用，刀3第0步 8/8 已验证 |
| **B 归组** | 散落名字收进对象（`x` → `state.x`）；逻辑不变 | `verify_rename.py` | ✅ 可用，已自检 |
| **C 语义分派** | 按证据类型重排分支（`AUDIT-S2-02` 第 1 步） | **无** | 🚫 **没有门，不许做** |

### A —— `verify_extract.py`

```bash
python3 refactor/tools/verify_extract.py <before> <after> \
    --src <原函数名> --moved <新函数名> \
    --block for|if|while|with|def|defs [--index N] \
    [--strip-call NAME=K]
```

- `--block def --index N`：取 before 侧第 N 个内嵌 `def` 的体，与提升后的模块级函数体比对。
- `--strip-call NAME=K`：after 侧把对 `NAME` 的调用的前 K 个位置实参剥掉再比——
  用于**级联提升**（提 `plan` 时在 51 处调用点插了 12 个捕获实参，剥掉才还原得回原体）。
- **复合门**：多刀连做之后，用**最原始那份留底**当 `before` 再验一次，
  证明「原始体 + 仅调用点插参」。这比逐刀验更强，不要省。
  整条链的复合门见 `compound_gate_knife1.py`（刀1 链 8 刀端到端封链；
  含一条已单独证过的公理——init 字面量提升——门头注释写明公理是什么、
  为什么可信任；新链的复合门照此形状写）。
- **调用点是门射程之外的新代码**（刀2 事故）：`--orelse`/`--slice`/`--block`
  这类锚点只覆盖**被搬走的块**；替代它的调用点（分派/return 包裹）是手写的，
  门看不见。抽取条件链时调用点必须过 `verify_dispatch.py`——
  它验「进入条件 ∪ 落空路径」与原链等价（前缀 test / 兜底 else 等价 /
  支体形状）。刀2 曾把 5 路链（含 raise ValueError 兜底）写成 2 路 if/elif
  无 else：两条路径死码、fail-closed 静默化——分派门就是为它造的。

### B —— `verify_rename.py`

```bash
python3 refactor/tools/verify_rename.py <before> <after> \
    --fn <函数名> --bind <对象变量名> \
    --names a,b,c | --names-file <每行一个> \
    [--dataclass <数据类名>]
```

它同时管三件事：

1. 每处 `bind.x` 还原成 `x` 之后，逻辑逐节点相同；
2. 从函数体里消失的初始化**恰好**是白名单里那些，不多不少；
3. 每条消失的初始化，其初值与数据类字段默认值 AST 相同
   （认得 `field(default_factory=list/dict/set)` 与 `field(default=...)`）。

还会抓两种偷渡：白名单外出现 `bind.<attr>`（搬家时顺手塞了新状态）、
语句条数不符（漏搬/多搬/换序）。

### C —— 为什么没有门

「把 50 个 `return plan(...)` 按证据类型分派成几段」会**改动分支顺序**。
`AUDIT-S2-02` 原文点名的失效模式正是「挡不住分支顺序错」。
要做它，先造一个能证明「同一输入走到同一个 `plan(...)` 出口」的门。
**门造出来之前，这一步不许开工**，哪怕看起来只是挪几个 `if`。

## 三、门的自检：造了门必须先证明它会 FAIL

一个从没抓到过错的门不是门。新造的门，先用**合成样本**试三种情形：

1. 正确变换 → 必须 PASS；
2. 偷改一处逻辑（把 `> 10` 改成 `>= 10`）→ 必须 FAIL；
3. 偷改一处**数据**（字段默认值 `0` → `1`）→ 必须 FAIL。

第 3 种最容易漏：逻辑等价但初值被改，`verify_extract.py` 完全看不见。
`verify_rename.py` 的自检记录见本文提交时的会话；照同样的方式验你新造的门。

## 四、一刀的标准流程

```
① 判类型   A / B / C？C 直接停手。
② 留底     cp <目标> refactor/work/<刀名>.before.py
③ 切       用执行器，不要手改（见五）
④ 验       对应的门，必须打印 PASS
⑤ 复查     python3 -c "import ast;ast.parse(open('<目标>').read())"
           python3 refactor/tools/layer_check.py     跨域引用数**不应变化**
⑥ 报       报实测行数变化与门的输出原文。失败就报失败，贴输出，不修饰。
```

⑤ 里那条的意义：**拆函数不应该改变跨域引用数**。变了说明动到了符号归属——
回滚重来，不要解释为什么可以接受。

## 五、写执行器的规矩

几千行的改动手改不现实，都要写执行器（放 `refactor/`，如 `_infra_cut.py`、
`_decide_once_step0.py`）。已经栽过的坑，照抄防御：

| 坑 | 症状 | 防御 |
|---|---|---|
| **`Path.read_text()` 洗掉 CRLF** | 生成的 diff 全 hunk FAILED；或落盘后整文件行尾被改 | 读写都用 `open(..., newline="")` 保字节 |
| **`AnnAssign` 被静默跳过** | 只处理 `ast.Assign`，`x: List[float] = []` 这类漏搬 | 两种都要接；漏搬会被门的「语句条数不同」抓到 |
| **函数内局部 `import`/绑定遮蔽** | `UnboundLocalError`；模块级补 import 救不了 | 改写前做**作用域碰撞检查**，撞了就插别名（`import X as _a1_X`） |
| **赋值目标名撞模块名** | `runabfe = getsource(runabfe)` → 必然 UnboundLocal | 同上，或重命名目标 |
| **f-string 里的字面量看不见** | 只收 `ast.Constant`，`f"..."` 的静态段在 `JoinedStr` 里 | 纯常量 f-string 当普通字面量；混合串的静态段逐段入账 |
| **多行插入文本塞进单个列表元素** | 生成的 diff 畸形、hunk 被拒 | 应用器按行拆开 |
| **门自检的合成样本落在仓库根** | 刀2 分派门自检把 b/g/bg/bt.py 写进了仓库根（2026-09-20 用户发现，已清） | 自检一律在 `/tmp` 或 `work/` 里跑；落盘前 `pwd` 检查 |

**执行器自带 fail-closed 检查**，检查不过就不写文件。`_decide_once_step0.py` 的三道
可以照抄形状：① 捕获闭包核实 ② 裸引用遮蔽分析 ③ 调用点范围。
**fail-closed 拦下来是好事**——上一轮它真的拦住过一次错误改写。

## 六、本仓特有的陷阱（都有实测事故背书）

| 陷阱 | 事故 | 规则 |
|---|---|---|
| **dict 被 `**` splat 进签名不匹配的函数** | 2026-09-19 真机 9/9 崩：`TypeError: got an unexpected keyword argument 'last_window_max_states'` | **显式形参，不 splat 裸 dict**。参数不匹配要在构造点炸，不要在展开点炸 |
| **并列清单靠人手同步** | `abfe_pipeline.py:16315` 身份元组 9 键、旁边字面量 8 键 ⟹ 指纹恒 `None` | **派生，不并列**。同一份清单只许一个来源 |
| **同一不变量多份实现** | 本仓历史最贵的 bug 形状（四份） | **一个不变量一处** |
| **`from X import *` 遇上可变模块全局** | `_PYMBAR_MODULE` 等 7 个被 `global` 改写的名字：`import *` 复制的是绑定快照，rebind 后旧模块仍看到 `None`，**且不报错** | 用 `import X` + 属性访问；re-export 只导函数不导变量 |
| **自产产物的 sha256 进缓存身份** | 已复发 4 次 | 只有用户输入才配做身份 |
| **改配置键作废全部窗口缓存** | `max_bias_warmup_steps` 那次 | 动之前先查指纹、把 GPU 代价摆出来 |

**重构期间这些陷阱怎么体现**：搬函数时顺手"整理"成 `**kwargs`、
把两处重复"统一"成一处却改了字节形态、把常量搬家时漏了一个——
前两条都会被门放过（因为 AST 确实等价或确实是搬运），所以**靠的是不去做**，
不是靠门。本计划里所有"合并重复实现"的动作都被明确排除在外，原因就在这。

## 七、门 FAIL 了怎么办

**唯一正确的反应：改代码，让门通过。**

🚫 不许放宽门的判据
🚫 不许给门加特例/白名单来绕过这一处
🚫 不许改测试断言去迁就新代码
🚫 不许加 `skip` / `xfail`

门 FAIL 说明这刀改了不该改的东西。如果你确信门判错了，**那就先修门并重新自检**
（三、），修完对**之前所有已过的刀**重跑一遍——门变了，旧结论就要重验。

## 八、数字对不上怎么办

范本是 2026-09-20 那次「预期 1365、实测 1357」：

1. **不糊过去**，也不直接改预期值；
2. 写一个**只读探针**，把「同一指标 × 多个历史状态 × 多种口径」全对一遍，
   先证明**变化不是这刀造成的**（那次证到了：三个状态在相同文件集下总数完全一致）；
3. 再定位差异来源（那次：1365 在任何可复现口径下都不出现，全仓无存档输出
   ⟹ 判定为上一会话的记忆数）；
4. **落盘勘误**，给出新基准。

结论只有两种是可接受的：「这刀确实改变了指标，原因是 X」或
「这刀没改变指标，原有数字是错的，勘误为 Y」。**没有第三种。**

## 九、什么时候算一刀做完

同时满足：

- [ ] 门打印 PASS（多刀连做的还要过**复合门**）
- [ ] `ast.parse` 语法合法
- [ ] `layer_check.py` 跨域引用数未变（变了要按八解释）
- [ ] 实测行数与 `CUTTING_PLAN` 的预期一致（不一致按八处理）
- [ ] 留底还在 `refactor/work/`
- [ ] **门调用方式已落盘**：`work/verify/<刀名>.verify.sh`（可直接跑的
      原样命令；before/after 用留底链——本刀的 after = 下一刀的留底，整链
      因此可逐刀重放）。复验时跑脚本，不要从叙述里重建参数
      （刀1 链 11 个脚本见 `work/verify/`，全部实跑绿）
- [ ] `PROGRESS.md` 落盘：这刀做了什么、指标、留底文件名、下一刀

**注意「达标」和「做完」不是一回事。** 刀做完了但单元仍 >400 行
（`CUTTING_PLAN` §0 判据 1），那是计划里明说要留给下一轮的，
不要自作主张继续切——下一刀要用户单独点名。
